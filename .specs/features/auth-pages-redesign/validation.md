## Ranked gap list

1. **(Medium) No regression test protects the OAuth-decorative-only contract (AUTHPG-06).** A future change making the Google/Microsoft buttons call a real endpoint would ship silently. Recommend at minimum one `OAuthButtons.test.tsx` asserting `handleClick` triggers no `fetch`/`apiFetch` call and only shows the toast.
2. **(Medium) No regression test protects `AuthLayout` adoption across all 6 pages (AUTHPG-03).** A future edit could drop the wrapper from one page (e.g. during an unrelated refactor) with no signal. Recommend a lightweight smoke test per page asserting the brand panel's `aria-hidden` SVG or the eyebrow text renders.
3. **(Low) No regression test protects the "no self-hosted badge" decision (spec.md Out of Scope, item 2).** Recommend one assertion in an `AuthLayout.test.tsx` that no "Self-hosted"/"SaaS" text node exists.
4. **(Low-Medium) AUTHPG-05 gap**: `SignupPage` has no visible "termos" (terms) text/checkbox, though the AC lists it as part of the required structure. Worth confirming with the spec author whether "termos" was meant to ship in this pass or was silently dropped; if intentional, spec.md should be updated to remove it from the AC wording.
5. **(Low-Medium) AUTHPG-09 gap**: the literal AC asks for a "Reenviar email" button on `VerifyEmailPage`, but the actual resend action lives on `SignupPage`'s post-submit pending screen instead. Recommend clarifying whether this is a spec-wording issue (resend was always meant to live on the pending-signup screen, not the token-verification landing page) or a real missing feature on `VerifyEmailPage`.
6. **(Info, not a gap)** `web/src/lib/branding.ts`'s `useBrandLogoUrl` predates this commit (`729fa05`) — correctly reused, not reimplemented, per AC AUTHPG-01.
